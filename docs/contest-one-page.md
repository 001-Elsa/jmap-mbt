# MoonJMAP：JMAP 邮件视图双 state 同步内核

**参赛方式**：个人、新生态项目；本人确认项目此前未参赛。**赛期**：官方十月页面公告报名和验收截止为2026年10月31日，十月最多提交3次。报名凭证和入群状态须本人核实。

**源码**：https://github.com/001-Elsa/jmap-mbt ｜ **包**：`001-Elsa/moonjmap@0.1.0` ｜ **许可**：Apache-2.0。

**需求**：JMAP的邮件对象变化和查询顺序变化使用两条独立state。查询顺序不变时属性仍会变化；删除成员后补位还必须保持同一queryState。直接混接响应或跳过对象历史会产生无法安全提交的邮件列表。

**交付**：以MoonBit实现固定邮件查询视图、双state追赶、最终排名归并、同状态前缀补位、对象覆盖检查、历史失效重建、预算与generation控制；输出下一请求、可恢复待办或Ready前缀。JMAP领域证书记录前缀位置来源并离线验证结构化边界。核心包不持有网络连接。

**实现理由**：Mooncakes已有集合对账、CDC、恢复、前缀门禁和审计类近邻；这些通用机制不作为本项目独占创新。独立库聚焦JMAP账户/查询身份、两条opaque state以及邮件前缀契约，避免把协议语义塞入通用工具。指定快照比较不保证零重合或通过判重。

**最小复现**：安装MoonBit后，克隆仓库，运行 `moon run cmd/demo --target wasm`。演示使用合成数据，建立基线，将乱序对象恢复为查询顺序，检查Ready并验证证书。开发者通过 `moon add 001-Elsa/moonjmap@0.1.0` 消费主库。

**验证**：86项MoonBit核心测试覆盖双state、补位、旧响应、预算和证书；排名归并93,072组、证书转移4,225种；独立oracle17例、固定向量与有界对拍15例。CI覆盖wasm/wasm-gc/JS的检查、构建、测试与演示，另做Python回归和源码归档验收。提交94575e9的四个远程CI job已通过，记录见逐项核查报告；后续提交以对应Actions记录为准。

**边界与来源**：不做HTTP/TLS/OAuth、邮件发送/正文附件、完整客户端或通用RPC。按RFC8620/8621设计，合成夹具和生成器来源已列入 `docs/source-provenance.md`。此前Stalwart v0.16.27本机只读互操作仅为有限外部证据，不代表生产或所有服务兼容。
