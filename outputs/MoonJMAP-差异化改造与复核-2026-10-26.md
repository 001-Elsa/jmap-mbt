## 已完成的改变

本次缩减通用变化接口、编辑脚本和指纹身份机制，把实现集中到 JMAP 邮件查询前缀。改造前四个生产 MoonBit 文件为 4,029 行、123,748 字节；改造后为 3,831 行、118,914 字节，减少 198 行、4,834 字节。这是代码规模变化，不是相似度百分比。

| 改造点 | 原实现 | 当前实现 | 实质影响 |
| --- | --- | --- | --- |
| 身份和请求绑定 | canonical 字符串、FNV-1a 风格 query/request 摘要 | 直接保存并比较结构化 `QueryKey` 和完整 typed `Request` | 删除 FNV 算法与摘要字段；不同服务/账号含分隔符也不能依赖拼接同串混用身份 |
| 证书解释方式 | 通用 remove/add 编辑脚本，生成并执行序列删除/插入 | `PrefixSlotWitness::FromBefore(index)` / `Introduced(id)` 对应新前缀每个位置 | 删除 `RemovedWitness`、证书 removed/added、操作生成和 patch 回放代码；移动直接引用旧位置 |
| 查询变化应用 | 每个 removed 重建数组，再逐 added 调用 insert | 过滤旧前缀存活项，按服务端最终 rank 与 added 归并，只构造目标连续前缀 | 主实现不再应用通用可变序列 patch；未知前驱仍 `NeedsRefresh`，不夹到尾部 |
| 邮件对象变化 API | RFC 三数组先投影到旧 `ChangesData{removed,updated,has_more}` 兼容路径 | 直接处理 `EmailChangesData{created,updated,destroyed,has_more_changes}` | 删除旧公开类型、envelope、两个旧响应枚举分支及兼容转换路径 |

位置证书示例：

```text
before = [a, b, c]
after  = [b, a, x]
slots  = [FromBefore(1), FromBefore(0), Introduced("x")]
```

`Introduced` 只说明 ID 新进入本地有界前缀，不能解释成服务器新建邮件。位置引用必须有效、不能重复、必须与 after ID 对应；旧 ID 不能伪装成 Introduced。

带 plan 的构造函数先将完整 Request 与 before 视图当前 planner 的输出直接比较，再校验固定 filter/sort/properties、请求 ID、账号/查询、expected states、分页和 maxChanges。可选绑定验证的是本地请求形状与领域约束，仍不认证网络来源。

## 保留的正确性条件

双 state 分开推进、同 queryState 连续补位、Email/get 按 ID 归位、generation fence、checkpoint、预算和 Ready 门禁仍保留。它们有技术先例，也有同步正确性用途。

RFC 三数组每个 wire 条目都消耗 maxChanges，跨集合重复仍计数；destroyed 优先于同页 updated 的取对象义务；created 使查询协调保持待办。分页未完成或预算耗尽时，不跳过历史，不推进成假 Ready。

独立 review 发现并修正了一处重构中新增的边界：Email/get 的 NotFound 可能合法地令 queryState 失效。绑定证书现在允许明确 NeedsRefresh/ProtocolFailure 下 `Some(token) → None`，仍拒绝替换为另一个 token、改变 IDs 或 total。实际 planner → accept_response(Error(NotFound)) → with-plan 证书已增加回归，review 复核关闭该问题。
