## 1. 真实 JMAP 服务互操作：已完成有界范围

已部署官方 Stalwart Server v0.16.27 aarch64 macOS 二进制，在临时 RocksDB 目录和 `127.0.0.1:8080` loopback HTTP 上运行。测试账号通过 Basic 凭据访问，凭据只存在于运行进程环境；测试邮箱中预先注入 5 封合成邮件，未使用私人邮件。

真实服务运行结果：

- Session：1 次 HTTP 200，返回 JMAP Core/Mail capability；
- `Email/query`：5 次，每次 5 个 ID，`total=5`；
- `Email/get`：5 次，每次 5 个对象，累计 25 个非空 Email 对象，`notFound=0`；
- `Email/changes`：5 次 HTTP 200，有效无变化响应；
- `Email/queryChanges`：4 次 HTTP 200，有效无变化响应，Stalwart 按 RFC 8620 省略可选 `total`；
- 20/20 HTTP 请求返回 2xx，没有失败项。

非空对象级记录由真实运行的脱敏 observations 派生，不重放请求、不生成响应：

- [对象级互操作记录](real-interop-stalwart-v0.16.27/record-seeded-object-level-20261026.json)
- [对象级互操作说明](MoonJMAP-真实对象级互操作证据-2026-10-26.md)
- [派生工具](../scripts/derive_real_interop_record.py)

早期 `record-complete-20261026.json` 是空 Inbox 的 typed-wire 探针记录，仍保留作协议发现证据，但不能代替上面的非空对象级记录。非空运行的原始响应体按脱敏策略没有保存，因此记录证明真实服务返回了非空对象和可解析响应形状；它不把非空对象重新喂给 typed decoder 的动作写成已经发生。

本次没有执行 JMAP `Email/set`/`Email/import` 写入，也没有制造创建、更新、删除或移动事件；因此“真实互操作已完成”的范围是 Session、查询、非空对象读取和无变化增量分支，不是完整写入或变化链兼容。
