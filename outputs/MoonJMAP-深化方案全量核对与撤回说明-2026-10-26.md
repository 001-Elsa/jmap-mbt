# MoonJMAP 深化方案全量核对与撤回说明

日期：2026-10-26。范围：当前 Mooncakes 发布快照、候选源码复核、本地原型评估与撤回、原有功能错误修复。没有发布、上传或赛事提交。

## 取舍结论

用户明确要求“如果改完反而增加了相似度就不要改”。据此，本轮 **撤回新增的载荷来源/trace 闭合审计层**，保留 MoonJMAP 原有“双状态邮件有序前缀同步 + 解释该前缀变化的领域证书”定位。

撤回依据不是新原型功能失效，而是全量检索发现的强架构邻居：`HhWw96/moontxnwitness@0.2.7` 已把实际字段来源、完整交付、列表前缀约束、原始 trace 和独立报告重算组织成一套审计流程。继续增加载荷/trace 审计，会扩大与它及 MedSeal 等项目的实质重合面。没有可靠的统一“相似度百分比”可证明新增方案使整体相似度下降，因此按用户的保守条件不纳入项目。

新增 `EmailPrefixExchange`、`EmailPrefixAudit`、采集辅助、exchange/trace verifier 及其文档、测试已移出 `src/` 和产品 `docs/`；公共 `.mbti` 重新生成，当前公共 API 不包含这些入口。探索原型只在 `work/differentiation-2026-10-26/rejected-proposal/` 保存，带撤回状态与 SHA 清单，不参与编译、测试发现或源码归档。这些原型不是当前已交付功能。

## 当前保留的改动

仅保留原有功能的正确性修复，没有新增审计产品层或公共 API：

- 部分重排 `[a,b,c] → [b,a,c]` 的旧证书生成失败已修复，保留原位 ID；全部 65 个有序子集间 **4,225 种转移**穷举，严格 verifier 不放宽。
- 现有 Query 不能超请求 limit；同 queryState 补位不能改 total；QueryChanges 按新 total 截断，修复增长时误丢新成员；拒绝重复/乱序最终索引及未先 removed 的缓存 ID 偷移位。
- 保留非空 state、本地无进展分页和预算契约，防止 request ID、轮数、字节与累计变更数溢出。最终页同 Email token 的保守变更仍可接受，并保留正常刷新义务。
- 更正旧证书文档边界：`objects_complete` 由生成器核查后记录，旧证书不含邮件字段，离线 verifier 不能重新证明字段完整性或来源。

这些修复不作为新增原创功能或降低相似度的证明。
